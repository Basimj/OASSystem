# Inventory V1 — Products UI Manual Test Plan

## الهدف
اختبار واجهة `/products` يدويًا قبل الانتقال إلى الواجهة التالية، والتأكد أن الأخطاء لا تكسر Blazor circuit أو توقف البرنامج، وأن البيانات تنتقل كاملة UI → API → DB → UI.

## معيار التحقق المرئي المشترك
لكل حقل إجباري قبل الضغط على حفظ:
- يظهر `*` أحمر بجانب الـLabel.
- إذا كانت القيمة مفقودة عند الحفظ: يظهر حد/توهج أحمر على الحقل ورسالة صغيرة تحته (`هذا الحقل إجباري.`).
- يظهر Snackbar عام: `هناك بيانات إجبارية لم يتم إدخالها.`.

لكل حقل اختياري:
- لا تظهر النجمة.
- يظهر `اختياري` داخل Placeholder عندما يكون الحقل فارغًا وقابلًا للتحرير.

للقيم غير الصحيحة:
- يظهر الخطأ على الحقل نفسه ولا يحدث Exception يوقف الصفحة.
- يظهر Snackbar عام يطلب مراجعة الحقول الحمراء.

- [ ] كود المنتج مطلوب (32).

- [ ] الاسم الإنجليزي اختياري (150).

### Frame / Sunglasses
- [ ] ترك تفاصيل الإطار كلها فارغة مسموح.
- [ ] بمجرد إدخال أي تفصيل إطار يصبح `الموديل` مطلوبًا.
- [ ] Model <= 100، Material <= 50، RimType <= 50، Gender <= 20، Shape <= 50.
- [ ] TempleLength / BridgeSize / LensWidth أرقام اختيارية ضمن decimal(6,2).
- [ ] إدخال نص أو أكثر من منزلتين عشريتين أو قيمة أكبر من precision يعطي خطأ موضعي ولا يوقف الصفحة.
- [ ] حفظ التفاصيل ثم إعادة فتح المنتج والتحقق من عودة كل القيم.

### Lens
- [ ] ترك تفاصيل العدسة كلها فارغة مسموح.
- [ ] بمجرد إدخال أي تفصيل عدسة يصبح `نوع العدسة` مطلوبًا.
- [ ] LensType <= 50، Material <= 50، Coating <= 50.
- [ ] RefractiveIndex قيمة رقمية ضمن decimal(5,3).
- [ ] Sphere/Cylinder/Add تقبل السالب والموجب ضمن decimal(6,2).

## اختبار Round-trip القياسي
لكل نوع سجل:
1. استخدم قيمًا مميزة يسهل البحث عنها (مثال `QA-PROD-001`, `QA-SKU-001`).
2. احفظ من الواجهة وتأكد من Snackbar النجاح.
3. نفذ `scripts/verify-inventory-products.sql` بعد ضبط القيم أعلى السكربت.
4. قارن كل عمود في DB بالقيمة المدخلة.
5. اضغط Refresh في الواجهة ثم افتح السجل من جديد.
6. قارن كل حقل بالقيمة المخزنة في DB.
7. عدّل عدة حقول، احفظ، وأعد الخطوات 3–6.

## شرط إغلاق اختبار الواجهة
لا ننتقل للمخازن حتى:
- جميع الحالات أعلاه Passed.
- لا يوجد unhandled exception أو Blazor circuit failure.
- لا توجد قيمة معروضة تختلف عن القيمة المخزنة.
- لا توجد قيمة يقبلها Application ثم ترفضها DB بسبب طول/نوع/precision معروف.
