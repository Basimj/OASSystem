# مراجعة تكامل المنتجات والمخزون

تاريخ المراجعة: 2026-09-26.
المصدر: OASSystem-main.zip المرفق بهذه المهمة.
المرجع: OpticalSystems_Product_Inventory_Integration_Task.md.

## النتيجة وحدود التحقق

النسخة الأصلية تحتوي بالفعل على غالبية التنفيذ المطلوب، بما فيه CreateStockProductCommand، واجهة الصنف الأول والرصيد الافتتاحي، وقاعدة المخزن الافتراضي. تم تتبع هذا المسار وإصلاح ثغرات في الحفظ والتحقق والعرض، مع الحفاظ على بقية أقسام المشروع.

**لم يتم تشغيل التطبيق أو إثبات نجاح Build/Tests في هذه البيئة: dotnet غير مثبت، ولا تتوفر قاعدة SQL Server للاختبار.** الاختبارات الجديدة مرفقة ولم تُنفَّذ. لذلك لا تعتبر شروط القبول المتعلقة باجتياز الاختبارات والواجهة مثبتة بعد.

## الإصلاحات الفعلية

1. **الحركة الافتتاحية الجديدة:** إزالة Update بعد Add من CreateStockProductCommandHandler. الحركة تظل Added حتى إدخالها عند Commit، بدل تحويلها إلى Modified وإصدار تحديث لصف غير موجود.
2. **الرصيد الجديد:** مستودع InventoryBalance يحافظ على Added عند Update. هذا يصلح أول وارد سواء جاء من شاشة المنتج أو مسار الترحيل الحالي.
3. **تعدد الحركات قبل الحفظ:** البحث أولًا في الأرصدة المتتبعة محليًا حتى لا ينشأ رصيد ثانٍ لنفس Warehouse + Variant قبل SaveChanges.
4. **دقة البيانات:** الكمية الافتتاحية تطابق decimal(18,3)، والتكلفة والأسعار تطابق decimal(18,2)، والقيمة الإجمالية ضمن سعة القاعدة. القيم الكبيرة والصغيرة جدًا تُرفض كتحقق بدل تسببها في استثناء حسابي.
5. **التكلفة الصفرية:** الصرف والنقل يستخدمان المتوسط الفعلي حتى عندما يكون صفرًا؛ لا يستبدلانه بتكلفة مدخلة ترفع قيمة مخزون مجاني.
6. **التحويل إلى غير مخزني:** منع إلغاء IsStockItem عند وجود رصيد أو سجل حركات، حتى عند عدم اختيار نوع SERVICE.
7. **واجهة المنتج:** حماية حساب الإجمالي من Overflow، وتعطيل الحقول والإلغاء أثناء الحفظ، وتطبيق علامة غير مخزني إذا كان النوع الافتراضي خدمة، وتحسين بعض التسميات العربية.
8. **واجهة الأرصدة:** اعتماد نتيجة آخر طلب مخزن فقط، وتصفير البيانات القديمة أثناء التحميل، وإظهار فشل التحميل بوضوح بدل إظهاره كأرصدة صفرية صحيحة.
9. **التصدير:** عرض الأصناف الفعالة بدون حركة بقيم صفرية عند تحديد مخزن، دون إنشاء InventoryBalance وهمي في القاعدة.

## مطابقة المتطلبات

| المتطلب | المسار/الحماية |
|---|---|
| منتج مخزني + أول Variant | CreateStockProductCommandHandler + Validator؛ قسم الصنف الأول داخل ProductsPage |
| خدمة غير مخزنية | SystemKey = SERVICE؛ تحقق الإنشاء والتعديل والواجهة |
| رصيد اختياري ومخزن فعال | OpeningInventoryRequest؛ اختيار الافتراضي الفعال في الواجهة والتحقق من وجود المخزن وتفعيله في الخادم |
| حركة Opening وLedger ومتوسط مرجح | إنشاء Transaction + Line، ثم InventoryPostingService، ثم Commit عبر المعاملة القائمة |
| عدم تخزين الكمية/المخزن في المنتج | الكيان Product لم يتغير؛ الرصيد في InventoryBalance |
| ظهور الأصناف بدون حركة | دمج عرض الأصناف الفعالة بأرصدة المخزن المحدد داخل الشاشة؛ تصدير متوافق |
| مخزن افتراضي فعال واحد | الفهرس UX_Warehouses_ActiveDefault والترحيل الأصلي 20260923090000 |
| منع الضغط المكرر | تعطيل الحفظ وإيقاف إعادة الدخول، وفهارس ProductCode/SKU/Barcode الفريدة داخل المعاملة |
| نتيجة الطلب المكرر | الطلب المطابق المكرر يُرفض بتعارض، ولا يعيد نتيجة الطلب الأول؛ ليست آلية replay idempotency بمفتاح مستقل |
| التزامن | RowVersion للرصيد والحركة مع تحويل تعارض EF في المسار العام القائم |
| التراجع الكامل | المعاملة القائمة تشمل الإنشاء والترحيل؛ أضيف اختبار SQL يجبر الفشل بعد SaveChanges وقبل Commit |
| إدارة أصناف إضافية وحركات لاحقة | الصفحات والمسارات الحالية محفوظة |
| حدود الطبقات | لا تغيير في مراجع المشاريع ولا اعتماد جديد من Client على Domain أو من Controller على DbContext |

لا توجد تغييرات مخطط قاعدة بيانات جديدة لهذه الإصلاحات. ترحيلات المخزون الموجودة في النسخة الأصلية يجب أن تكون مطبقة، ومنها فهارس التفرد وقواعد ProductType. لا يشمل اختبار EnsureCreated المضاف اختبار ترقية قاعدة بيانات قديمة عبر جميع Migrations.

## خطوات التحقق على بيئة التشغيل

من مجلد OASSystem:

```powershell
dotnet build OASSystem.sln
dotnet test OAS.Tests/OAS.Tests.csproj --filter "FullyQualifiedName~OAS.Tests.Inventory"
```

اختبارات SQL الجديدة تتخطى نفسها إذا لم يحدد المتغير التالي. استخدم حساب اختبار له صلاحية إنشاء قاعدة مؤقتة؛ تنشئ الاختبارات قاعدة مستقلة باسم OAS_Inventory_Test_<guid> وتحذفها بعد الانتهاء، ولا تعدل قاعدة الاتصال المقدمة:

```powershell
$env:OAS_INVENTORY_TEST_SQLSERVER = "Server=localhost;Integrated Security=True;TrustServerCertificate=True"
dotnet test OAS.Tests/OAS.Tests.csproj --filter "TestCategory=InventorySqlServer"
```

هذه الاختبارات تستخدم إعدادات EF الحقيقية ومستودعات المشروع ومعاملة EfUnitOfWork، مع مولد أرقام اختبار. تغطي: الحفظ الكامل، وعدم إدخال رصيد مصطنع، وفشل بعد الكتابة ثم Rollback، وطلبَي إنشاء متزامنين مكررين، ورفض كتابة رصيد بنسخة RowVersion قديمة. الاختبار الأخير يتحقق من تعارض كاتبين على الرصيد، وليس اختبار حمل شاملًا لكل مسارات HTTP.

### اختبار يدوي للواجهة

1. أنشئ مخزنًا فعالًا وافتراضيًا، وتصنيفًا ونوعًا فعالين.
2. أضف منتجًا مخزنيًا مع SKU أول، وافتح قسم الرصيد الافتتاحي. تحقق من اختيار المخزن الافتراضي ومن إمكان تغييره.
3. أدخل 10 وحدات بتكلفة 100. بعد الحفظ المتوقع: رصيد 10 ومتوسط 100 وقيمة 1000، وحركة Opening مرحّلة وقيد Ledger.
4. أضف واردًا آخر 10 بتكلفة 200. المتوقع: رصيد 20 ومتوسط 150 وقيمة 3000.
5. أنشئ منتجًا ثانيًا دون رصيد افتتاحي. يجب ظهوره بصفر عند اختيار المخزن، دون صف رصيد فعلي. تحقق من وجوده في التصدير أيضًا.
6. أنشئ خدمة وتحقق من إخفاء الصنف المخزني والافتتاحي. اختبر رفض طلب API مخالف كذلك.
7. جرّب كمية صفرية أو سالبة، تكلفة سالبة، منازل عشرية زائدة، وقيمًا كبيرة جدًا. يجب ظهور خطأ تحقق دون انهيار الصفحة.
8. بدّل المخزن بسرعة ثم حدّث الصفحة؛ يجب ألا تستبدل استجابة قديمة أرصدة المخزن الحالي. عند فشل الطلب يجب ظهور رسالة فشل، لا قائمة أصفار مضللة.
9. حاول تكرار الحفظ والكود وSKU والباركود. يجب ألا تتكرر المنتجات أو الحركة الافتتاحية.
10. أضف Variant ثانيًا وتحقق من استقلال أرصدته. انقل 5 وحدات إلى مخزن آخر وتحقق من حفظ الكمية والقيمة، وكرر بتكلفة افتتاحية صفرية.
11. حاول إلغاء IsStockItem لمنتج له حركات؛ يجب الرفض. جرّب جعل مخزنين افتراضيين فعالين؛ يجب أن تمنع القاعدة ذلك.

## ما لم يتم إثباته في هذه البيئة

- نجاح بناء الحل والاختبارات، بما فيها اختبارات الأقسام الأخرى الموجودة أصلًا.
- التشغيل الفعلي للواجهة والصلاحيات عبر HTTP واختبارات المصادقة المتكاملة.
- ترقية قاعدة SQL Server قائمة أو اختبار جميع Migrations.
- اختبارات الضغط والأداء على كتالوج كبير؛ الشاشة الحالية تستمر في جلب الصفحات ودمج العرض في العميل.

لا تتضمن النسخة ادعاء اجتياز أي من هذه الاختبارات دون تشغيلها.
