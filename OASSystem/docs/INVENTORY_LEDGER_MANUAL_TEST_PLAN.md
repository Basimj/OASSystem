# Inventory V1 — Inventory Ledger UI Manual Test Plan

## الهدف
اختبار واجهة `/inventory/ledger` يدويًا والتأكد من أن جميع بيانات Inventory Ledger المعروضة تطابق قاعدة البيانات، وأن البحث والفلاتر والتنقل تعمل بدون تعديل مباشر على الـLedger وبدون Exceptions توقف التطبيق.

## قاعدة أساسية
واجهة Inventory Ledger هي **Read-only بالكامل**:
- لا يوجد Create.
- لا يوجد Edit.
- لا يوجد Delete.
- لا يوجد Post من هذه الصفحة.

أي تعديل على الـLedger يجب أن ينتج فقط من منطق Post للعمليات المخزنية أو الجرد وفق الـApplication/Domain الحالي.

---

## 1) تحميل الصفحة
- [ ] فتح `/inventory/ledger` لا ينتج Exception.
- [ ] يظهر Loading أثناء التحميل ثم يختفي دائمًا سواء نجح الطلب أو فشل.
- [ ] عند انقطاع API يظهر Feedback مناسب ولا يتوقف Blazor circuit.
- [ ] الصفحة لا تكتفي بأول 200 Ledger entry؛ جميع الصفحات يتم تحميلها.
- [ ] جميع Transactions اللازمة لعرض أرقام الحركات يتم تحميلها وليس أول 200 فقط.
- [ ] جميع Warehouses / Products / Variants اللازمة للعرض يتم تحميلها.
- [ ] سجل قديم مرتبط بمخزن غير نشط يظل ظاهرًا ويعرض اسم المخزن مع `(غير نشط)` بدل فقد الاسم.

---

## 2) صحة الأعمدة المعروضة
لكل سجل اختره من SQL وقارنه مع UI:
- [ ] التاريخ = `MovementDate` بعد عرضه بالتوقيت المحلي.
- [ ] رقم الحركة = `TransactionNumber` للعملية المرتبطة.
- [ ] نوع الحركة يطابق `MovementType`: `1 = وارد`، `2 = صادر`.
- [ ] المنتج والـVariant صحيحان.
- [ ] SKU صحيح.
- [ ] المخزن صحيح.
- [ ] QuantityIn تظهر **3 منازل عشرية**.
- [ ] QuantityOut تظهر **3 منازل عشرية**.
- [ ] BalanceAfter يظهر **3 منازل عشرية**.
- [ ] UnitCost تظهر منزلتين عشريتين.
- [ ] AverageCostAfter يظهر منزلتين عشريتين.
- [ ] InventoryValueAfter يظهر منزلتين عشريتين.
- [ ] مصدر الحركة يعرض نوع العملية، ويعرض `ReferenceType` عند وجوده.
- [ ] لا توجد خلية تعرض `null` كنص أو تسبب Exception؛ القيم غير المتوفرة تظهر `—` عند الحاجة.

---

## 3) اختبار اتجاه الحركة
### MovementType = In
- [ ] `QuantityIn > 0`.
- [ ] `QuantityOut = 0`.
- [ ] القيمة المعروضة في عمود داخل تطابق SQL بدقة 3 منازل.

### MovementType = Out
- [ ] `QuantityOut > 0`.
- [ ] `QuantityIn = 0`.
- [ ] القيمة المعروضة في عمود خارج تطابق SQL بدقة 3 منازل.

### Transfer
لكل Transaction Line مرحّل:
- [ ] يوجد Ledger Out من مخزن المصدر.
- [ ] يوجد Ledger In إلى مخزن الوجهة.
- [ ] كلا السجلين مرتبطان بنفس `TransactionLineId`.
- [ ] الكمية في كل اتجاه تطابق Quantity في Transaction Line.

---

## 4) البحث
اختبر البحث بالقيم التالية كل واحدة على حدة:
- [ ] Transaction Number.
- [ ] اسم المنتج العربي.
- [ ] Variant Name.
- [ ] SKU.
- [ ] Barcode.
- [ ] Product Code.
- [ ] اسم المخزن.
- [ ] ReferenceType عندما يكون موجودًا.
- [ ] البحث بقيمة غير موجودة يعرض Empty State ولا يسبب خطأ.
- [ ] مسح البحث يعيد جميع النتائج الحالية.

---

## 5) فلتر المخزن
- [ ] `كل المخازن` يعرض جميع النتائج.
- [ ] اختيار مخزن يعرض فقط `WarehouseId` المطابق.
- [ ] المخازن غير النشطة التي لها Ledger تاريخي متاحة في الفلتر ومعلّمة `(غير نشط)`.
- [ ] تغيير المخزن عدة مرات لا يسبب Request/Render error.

---

## 6) فلتر نوع الحركة
- [ ] `كل الحركات` يعرض In وOut.
- [ ] `وارد` يعرض فقط `MovementType = 1`.
- [ ] `صادر` يعرض فقط `MovementType = 2`.
- [ ] الدمج بين فلتر المخزن ونوع الحركة يعطي تقاطع الفلترين بشكل صحيح.

---

## 7) فلتر التاريخ
- [ ] `من تاريخ` وحده يعرض نفس اليوم وما بعده.
- [ ] `إلى تاريخ` وحده يعرض نفس اليوم وما قبله.
- [ ] وضع التاريخين يعرض النطاق شاملًا لليومين.
- [ ] يوم يحتوي أكثر من حركة يعرضها كلها.
- [ ] إذا `من تاريخ > إلى تاريخ` يظهر خطأ أحمر على حقلي التاريخ ورسالة واضحة ولا يحدث Exception.
- [ ] تصحيح التاريخ يزيل الخطأ ويعيد النتائج تلقائيًا.

> المقارنة في UI تتم على التاريخ المحلي المعروض للمستخدم، لذلك عند المقارنة مع SQL انتبه إلى Offset الموجود في `MovementDate`.

---

## 8) الفلاتر المرتبطة من الصفحات الأخرى
### من أرصدة المخزون
- افتح Ledger باستخدام زر حركات الصنف من صفحة الأرصدة.
- [ ] URL يحتوي `variantId`.
- [ ] تظهر فقط حركات Product Variant المحدد.
- [ ] زر `إلغاء التصفية المرتبطة` يظهر.
- [ ] الضغط عليه يعيد `/inventory/ledger` ويعرض كل الحركات.

### من عملية مخزون
- افتح Ledger مع `transactionId` إذا تم الوصول إليه عبر رابط مرتبط.
- [ ] تظهر فقط سجلات العملية المحددة.
- [ ] عند Transfer تظهر سجلات In وOut للعملية نفسها.

---

## 9) فتح تفاصيل الحركة
من أي صف:
- [ ] زر `الحركة` يفتح `/inventory/transactions?transactionId=<id>`.
- [ ] صفحة العمليات تفتح نفس العملية الصحيحة.
- [ ] رقم العملية والبنود في صفحة العمليات تطابق صف الـLedger.
- [ ] لا يحدث خطأ إذا كانت العملية قديمة أو مرتبطة ببيانات غير نشطة.

---

## 10) فتح تفاصيل الصنف
من أي صف:
- [ ] زر `الصنف` يفتح `/products?productId=<id>`.
- [ ] صفحة المنتجات تفتح المنتج الأب الصحيح للـVariant.
- [ ] SKU/Variant الموجود في الـLedger تابع فعلًا لنفس المنتج.

---

## 11) التحقق من قاعدة البيانات — Round-trip Read
استخدم `scripts/verify-inventory-ledger.sql`:
1. ضع رقم Transaction في `@TransactionNumber`، أو اتركه NULL لعرض أحدث الحركات.
2. قارن كل الأعمدة المعروضة في UI مع ناتج SQL.
3. تأكد أن الاختبارات في Result Set الخاص بـ`PASS/FAIL` كلها PASS.
4. خصوصًا تحقق من:
   - Transaction Status = Posted.
   - TransactionLineId ينتمي لنفس TransactionId.
   - ProductVariantId في Ledger يساوي ProductVariantId في Transaction Line.
   - Quantity In/Out تتوافق مع MovementType.
   - Quantity الحركة تطابق Quantity في Transaction Line.

---

## 12) أكثر من 200 سجل
اختبار إلزامي قبل اعتماد الصفحة:
- [ ] جهز أكثر من 200 Ledger entry.
- [ ] افتح الصفحة بدون أي فلتر مرتبط.
- [ ] عدد النتائج يساوي عدد سجلات Ledger في DB ضمن البيانات المتاحة للمستخدم.
- [ ] ابحث عن Transaction موجود بعد السجل رقم 200 وتأكد أنه يظهر.
- [ ] لا يحدث تكرار للسجلات بين الصفحات التي تم تحميلها.

---

## 13) حالات الحماية
- [ ] API متوقف عند فتح الصفحة: Feedback فقط، لا crash.
- [ ] API يتوقف أثناء Refresh: Loading ينتهي وFeedback يظهر.
- [ ] Transaction lookup غير متوفر مؤقتًا: الصفحة لا تتوقف.
- [ ] Product/Variant/Warehouse تاريخي غير موجود بصورة غير متوقعة: تعرض `—` بدل Exception.
- [ ] قيم Decimal الكبيرة ضمن حدود schema تعرض بدون قطع أو تحويل خاطئ.

---

## معيار اجتياز واجهة Ledger
تعتبر الواجهة Passed فقط إذا:
- جميع حالات العرض والفلاتر والبحث والتنقل ناجحة.
- القيم المعروضة تطابق SQL.
- لا يوجد تعديل مباشر للـLedger.
- لا يوجد unhandled exception في أي حالة اختبار.
- جميع اختبارات PASS/FAIL في سكربت التحقق ناجحة للعمليات المختبرة.
