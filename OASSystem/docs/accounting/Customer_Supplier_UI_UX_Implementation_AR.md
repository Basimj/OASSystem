# تنفيذ تحسينات واجهات العملاء والموردين — الدفعة الأولى

تاريخ المراجعة: 2026-10-30

## المنفذ

1. تفعيل تبويبات العملاء الموجودة أصلًا في حالة الصفحة وعرضها في الواجهة، مع تبويب «جميع العملاء» ثابت، وتبويبات قابلة للإغلاق لكل سجل جديد أو موجود.
2. الحفاظ على نموذج العميل عند الانتقال إلى تبويب القائمة، مع استمرار طلب التأكيد قبل إغلاق تبويب يحوي تغييرات غير محفوظة.
3. وضع تبويبات الموردين بجوار شريط الأوامر، باستخدام البنية الموجودة في UiAccountingWorkspace.
4. إضافة رابط مباشر إلى «المركز المالي» في كل سجل بقائمة الموردين، دون وضع رابط داخل زر فتح السجل.
5. استبدال مرشحات الحالات المرقمة في مركز المورد بأسماء الحالات المعروفة حسب نوع المستند، وإعادة ضبط المرشح عند تغيير التبويب أو نوع مستند المشتريات.
6. استبدال حقل عملة المورد النصي بقائمة العملات المحملة من النظام؛ فشل تحميل العملات لا يمنع إظهار كشف المورد.
7. ربط أرقام القيود في كشف حساب العميل بالقيود الفعلية، وتوفير «فتح القيد» في جدول المستندات بدل عرض GUID.
8. عرض أسماء عربية للأنواع الشائعة من مستندات حركة العميل، مع إبقاء النص الأصلي للأنواع غير المعروفة.
9. مراجعة إجمالي دفعة الأرصدة الافتتاحية للموردين وعدد مستنداتها ومورديها وعملاتها، ثم طلب تأكيد قبل الترحيل. لم يتغير أمر الترحيل الخلفي ولا قواعده.
10. تحسين الاستفادة من ارتفاع الشاشة بعد إضافة تبويبات العملاء، وإضافة أنماط تتبع متغيرات الثيم إلى صفحات تقارير الموردين.

## ما لم يتغير

- لا تعديلات على أوامر الدومين أو شروط الترحيل أو API أو قواعد البيانات.
- لا تغيير لطريقة حفظ بيانات العملاء والموردين أو العقود أو رمي الاستثناءات.
- لم تُنفذ وظائف الربط بقيد موجود عبر البحث برقم القيد، ولا نقل تصفية مدينة العملاء إلى الخادم؛ هذه خطوات لاحقة.
- لم تُغيّر آلية تصدير Excel أو CSV أو منطق تجميع الأرصدة.

## اختبارات تشغيل مطلوبة

- فتح عدة عملاء وإنشاء عميل جديد ثم التبديل بينها وبين «جميع العملاء»؛ إغلاق تبويب معدل ينبغي أن يطلب تأكيدًا.
- فتح مورد من القائمة ثم استخدام «المركز المالي» من صفه؛ التبويبات والإجراءات في عرض الشاشة الواسع والضيق.
- تبديل حالة مستندات المورد حسب النوع (أوامر الشراء، الفواتير، السندات، المرتجعات) والتأكد من ظهور الخيارات الصحيحة.
- تجربة اختيار جميع العملات وعملة محددة عند توفر العملات، ومع فشل تحميل القائمة.
- فتح القيد المرتبط من كشف الحساب ومستندات العميل؛ القيود غير المرتبطة تظهر شرطة لا GUID.
- حفظ دفعة أرصدة افتتاحية كمُسودة ثم تجربة الإلغاء والتأكيد قبل ترحيلها على بيانات اختبار.
- اختبار 1366×768، تكبير 125% و150%، RTL، والثيم المظلم.

تم فحص مسارات الملفات وتطابق الاستدعاءات الجديدة مع مكوّنات المشروع وفحص سلامة ZIP. لم يتوفر .NET SDK أو قاعدة بيانات تشغيل لاختبار البناء والتكامل الفعلي.
