# توحيد تصميم الموردين مع العملاء

## نطاق التعديل
- استخدام نفس بنية وأسلوب قائمة العملاء: العنوان والإحصاءات والبحث والفلاتر والجدول والعرض للجوال والاستيراد والتصدير.
- استخدام نفس تصميم ملف العميل في عرض وإضافة وتعديل المورد، مع إبقاء الخصائص الخاصة بالمورد: نطاق المورد، الحد الائتماني، مدة السداد، مدة التوريد، والحساب الرئيسي عند الإنشاء.
- تبويبات الموردين: جميع الموردين ثابتة، وتبويبات السجلات قابلة للإغلاق، مع تنبيه التعديلات غير المحفوظة.
- ربط المركز المالي، أعمار الديون، والأرصدة الافتتاحية بمساراتها الحالية.
- عدم تعديل API أو Domain أو خدمات الحفظ المحاسبي.

## اختبار القبول قبل الإنتاج
1. فتح قائمة الموردين وتبديل الوضع الفاتح والمظلم، ومقارنتها بقائمة العملاء.
2. البحث والفلاتر (الحالة/الفرد أو المنشأة/المورد المحلي أو الدولي)، وتغيير الصفحة والفرز.
3. إنشاء مورد مع حساب أب مؤهل، والتحقق من الحفظ وفتح التفاصيل باسم المورد.
4. تعديل الاسم والشروط التجارية ومدة التوريد، وحفظ السجل، والرجوع إلى القائمة دون فقد المسودات.
5. إغلاق تبويب به تغييرات غير محفوظة واختبار نافذة التأكيد.
6. فتح المركز المالي من الصف ومن تفاصيل المورد، واختبار الاستيراد والتصدير.
7. اختبار العرض على شاشات 1366×768 والجوال، والتكبير 125% و150%.

**التحقق:** أجريت فحوصات ثابتة على مصادر الملفات والروابط والحقول، ولم أجرِ dotnet build لغياب .NET SDK في بيئة التنفيذ.
