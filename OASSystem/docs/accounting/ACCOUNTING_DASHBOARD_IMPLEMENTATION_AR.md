# تنفيذ لوحة المحاسبة الرئيسية — OASSystem

**المسار:** `/accounting`  
**المرجع المرئي المعتمد:** `docs/accounting/accounting-dashboard-approved-reference.png`

## ما تم تنفيذه

- واجهة RTL تستلهم الصورة المعتمدة وتبقي الشريط الجانبي والشريط العلوي لتطبيق OAS الحالي دون إنشاء غلاف مكرر.
- رأس يعرض الفترة وحالتها وتواريخها ووقت آخر تحديث ناجح، مع إعادة محاولة واضحة إذا فشل التحديث.
- أزرار إنشاء قيد يومي وسند قبض وسند صرف؛ يتم فتح محرر المستند الجديد فعلًا عبر `?new=true`.
- أربع بطاقات تشغيلية من خدمة لوحة المحاسبة القائمة، مع تفصيل حالات القيود (مسودة/بانتظار الاعتماد/معتمد).
- قسم ملخص مالي بأربع بطاقات: صافي أرصدة الحسابات البنكية النشطة، الأرصدة المدينة للعملاء، الأرصدة الدائنة للموردين، سندات المصروفات المرحلة داخل الفترة.
- جدول آخر خمس أنشطة: النوع، المرجع، الوصف، الحالة، الزمن، وروابط مباشرة لقيود وسندات محددة.
- تنبيهات ومهام قابلة للفتح، مع مرشح فعلي للقيود على الخادم (`?status=pending|approved|draft|unposted`).
- أربع مجموعات وصول سريع إلى الإعداد المحاسبي، العمليات اليومية، العملاء والموردين، والتقارير المالية.
- CSS خاص بالمكون مع تخطيط متجاوب، حالة تركيز واضحة، دعم الطباعة، وتقليل الحركة.

## مصدر الأرقام (لا توجد بيانات وهمية)

- الأرقام المالية تقرأ من قاعدة بيانات OAS وليست القيم التوضيحية في الصورة.
- جميع مبالغ دفتر الأستاذ **بالعملة الأساسية** وبقيم `DebitAmount` و`CreditAmount`، ومن قيود مرحّلة حتى تاريخ اليوم.
- **البنوك:** صافي المدين ناقص الدائن لحسابات GL المرتبطة بالبنوك النشطة فقط، وقد يكون سالبًا.
- **العملاء:** مجموع الأرصدة المدينة الموجبة للحسابات المرتبطة بالعملاء (لا يتم طرح المراكز الدائنة لطرف آخر لإخفائها).
- **الموردون:** مجموع الأرصدة الدائنة الموجبة للحسابات المرتبطة بالموردين.
- **المصروفات:** مجموع `Expense.Amount` لسندات المصروفات بحالة Posted وتاريخ المصروف بين بداية الفترة الحالية وتاريخ اليوم. لا يشمل كل المصروفات الدفترية أو التسويات التي ليست سند مصروف.
- لا تعرض الملخصات المالية دون عملة أساسية محددة؛ وتُعرض رسالة تهيئة بدل قيم مفبركة.
- دقة الكسور حسب تعريف العملة الأساسية (0 إلى 6 خانات).
- لا تعرض نسب تغيير شهرية أو رسوم اتجاه تخيلية؛ يلزم مصدر مقارنة حسابي معتمد لإضافتها.

## نقاط فحص بعد تشغيل النظام

1. التأكد من نجاح `dotnet build` و`dotnet test` في بيئة تتوفر فيها حزمة .NET المناسبة وSQL Server عند اختبار التكامل.
2. التحقق من تطابق قيم البنوك والعملاء والموردين مع تقارير الأستاذ والذمم لنفس التاريخ والعملة.
3. التحقق من أن إجمالي سندات المصروفات المرحلة يطابق تفاصيل مصروفات الفترة، وأن المستخدم يفهم اختلافه عن حساب المصروفات في ميزان المراجعة.
4. اختبار `?new=true` في القيود وسندات القبض والصرف، وروابط `?voucherId=...` لكل نوع.
5. اختبار `?status=draft`, `pending`, `approved`, `unposted` وتصفح الصفحات والبحث والعودة إلى عرض الكل.
6. اختبار فقد الاتصال/استجابة فارغة دون الادعاء بأن المعلومات حديثة.
7. اختبار واجهة RTL على 1366×768 والتكبير 125% و150% وعلى الأجهزة الصغيرة والوضع الداكن.
8. اختبار تحميل البيانات المالية بأحجام كبيرة ومراجعة الفهارس قبل النشر؛ أضيفت استعلامات تجميع للوحة.

**حدود التحقق في حزمة التسليم:** لم تتوفر أداة `dotnet` أو خادم SQL Server في بيئة الإعداد، لذلك لم يتم إجراء بناء أو تشغيل أو اختبار قاعدة بيانات حي. يجب عدم اعتبار الكود جاهزًا للنشر قبل هذه الاختبارات.
