# تنفيذ تصميم إضافة سند القبض والصرف — OASSystem

**التاريخ:** 1 نوفمبر 2026  
**أساس العمل:** الحزمة المصححة `OASSystem_Receipt_Payment_UI_Fixed_RZ1010.zip`، والتصميم المرئي العربي الذي اعتمده المستخدم.

## النطاق المنفذ

- إعادة تصميم محرري إضافة/عرض سند القبض والصرف، مع الإبقاء على التبويبات الموجودة في مساحة المحاسبة وإجراءات القائمة العليا (حفظ، اعتماد، ترحيل، إلغاء، وطباعة) دون نسخ إجراءات غير قابلة للتنفيذ داخل الصفحة.
- عنوان واضح ورقم السند وتاريخه وحالته ونوعه والعملة الأساسية والبيان العام. **الفترة المالية ليست حقلًا قابلًا للاختيار في موديل السند الحالي**؛ تم عرض تنويه أن صلاحية تاريخ السند تُفحص عند الحفظ بدل اختراع فترة أو مسار API جديد.
- ملخص جانبي يعرض إجماليات السند حسب عملاته، والإجمالي الأساسي إذا توافرت أسعار الصرف المطلوبة، وعدد الأسطر، وحالة اكتمال المعاينة. تظهر القيمة المحفوظة بتمييز منفصل.
- محرر لسطر واحد محدد في الأعلى مع نوع الطرف واختياره وطريقة الدفع ومصدره والعملة والمبلغ والسعر والبيان والمرجع؛ أسفل المحرر جدول متكامل للأسطر الحالية، مع تحرير السطر المحدد وحذف السطر وإضافة سطر جديد.
- بقيت أسطر السند مستقلة في العملة والطرف وطريقة السداد ومصدره كما في عقود الواجهة والخادم؛ **لم تُنقل بيانات السطر إلى رأس السند فعليًا**.
- فتح تبويب «المراجعة المالية» يبقي بيانات السند ويعرض الإجماليات والمراجعات؛ التبويب «بيانات السند» يعرض الجدول والنموذج والمراجعة أسفله.
- مراجعة إرشادية قبل الاعتماد: توفر الطرف، ومصدر الدفع، والمبالغ والعملات، وسعر الصرف، ومرجع الشيكات. هذه مؤشرات واجهة ولا تحل محل التحقق في الخادم.
- الحفاظ على رابط القيد الناتج وتنبيه عدم تخصيص فاتورة المورد تلقائيًا في سندات الصرف.
- إضافة CSS مخصص للقالب مع متغيرات الثيم الموجودة، وحالات تركيز واضحة وتمرير أفقي للجدول في المساحات الضيقة.

## ملاحظات تقنية

- البيانات والأحداث الأصلية بقيت متصلة بـ `ReceiptVoucherEditor.FormModel` و`PaymentVoucherEditor.FormModel` و`OnModelChanged` و`AccountingWorkspaceHost`.
- تغيير السطر داخل جدول الأسطر يختار **الكائن نفسه** الموجود في `Model.Lines`؛ ولذلك لا يُنشأ موديل منسوخ قد يضيع عند تبديل الصفوف.
- حالة إدخال سعر صرف يدوي غير مكتمل محفوظة داخل السطر، وتظل ظاهرة عند الرجوع إلى تبويب الإدخال.
- عملة رأس السند في الصورة هي عرض للـ **عملة الأساسية**، وليست عملة إجبارية لكل الأسطر. لكل سطر عملته الخاصة.
- الجدول يعرض فئة الحساب/الطرف أو اسم الحساب المقابل عند توفره؛ لا يُظهر رقم GL تخمينيًا للمورد أو العميل لأن الكائن الحالي لا يحمل رقم الحساب المرتبط.
- النصوص والأرقام في التصميم المرفق مجرد أمثلة مرئية وليست بيانات حقيقية؛ لم تُحقن أمثلة ثابتة في الواجهة.

## اختبارات التشغيل المطلوبة على جهاز المطور

1. `dotnet restore OASSystem.sln` ثم `dotnet build OASSystem.sln -c Debug` باستخدام .NET 9.
2. فتح صفحة القبض، إضافة سند، اختيار عميل وعملة وصندوق/بنك، إدخال مبلغ وبيان، ثم حفظ السند في وضع المسودة.
3. فتح صفحة الصرف وإنشاء سند مورد، ثم سطر آخر مختلف في العملة وطريقة الدفع، والتأكد من حفظ كل سطر على حدة.
4. إضافة سطرين وتعديل السطر الأول من الجدول ثم الرجوع للثاني؛ التحقق من عدم ضياع قيمة أي سطر.
5. تجربة سعر صرف يدوي غير مكتمل، ثم إدخال السعر، والتأكد من تحديث الإجمالي الأساسي المعروض وإظهار التحذيرات الصحيحة.
6. التبديل إلى تبويب المراجعة والعودة، والتأكد من بقاء جميع المدخلات.
7. اختبار فتح القيد، واعتماد المسودة وترحيل السند وفق الصلاحيات وحالات النظام الحالية.
8. اختبار الوضعين المظلم والفاتح بدقة 1366×768 وتكبير المتصفح 125% و150%، وباللغة العربية والتمرير الأفقي للجدول.

**حدّ التحقق:** لم تكن .NET SDK أو SQL Server مثبتة في بيئة إعداد هذه الحزمة؛ تم إجراء فحوصات سلامة الملفات وبنية Razor الساكنة فقط، ولم يُجرَ بناء تنفيذي أو اختبار تفاعلي على المتصفح أو قاعدة البيانات. لا تُنشر النسخة في الإنتاج قبل ذلك.
