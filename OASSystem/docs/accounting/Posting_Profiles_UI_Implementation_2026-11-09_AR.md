# تنفيذ تحسين ملفات الترحيل الآلي — OASSystem

**التاريخ:** 9 نوفمبر 2026  
**مصدر النسخة:** OASSystem_Fiscal_Periods_Cost_Centers_2026-11-07_Complete.zip، بعد تعديلات القوائم المدمجة السابقة.  
**النطاق:** واجهة عرض ملفات الترحيل، إضافة وتعديل ملفات الترحيل، قواعد الحسابات، تفعيل وتعطيل الملفات، وفلاتر البحث، مع اختبارات تطبيق محدثة.

## ما تغير

1. **قائمة مدمجة من سطرين:** تعرض اسم الملف والكود والوحدة والمستند وعدد القواعد وحالة النشاط. يعتمد التخطيط على `UiAccountingRecordList` و`FinancialStyle` الموجود من التعديلات السابقة، ولا يكرر المكونات.
2. **ملخص أعداد صحيح المصدر:** أعداد إجمالي الملفات والنشطة والمعطلة تُجلب من إجمالي نتائج الخادم، مستقلة عن مرشحات القائمة الحالية؛ وعند تعذر الجلب تظهر علامة «—» بدل رقم صفر مضلل.
3. **بحث وفلاتر خادمية:** الوحدة، نوع المستند، والحالة؛ تُدمج شروط البحث والحالة والوحدة والمستند في تعبير SQL واحد قبل الترقيم.
4. **نماذج بيانات بالعربية:** اختيار وحدة التشغيل ونوع المستند من قوائم عربية مترابطة؛ تبقى الرموز البرمجية الداخلية كما هي. تُعرض القيم التاريخية غير المدرجة دون تغييرها تلقائيًا.
5. **محرر قواعد عملي:** أسماء الأدوار العربية بحسب نوع المستند، زر إضافة الأدوار المقترحة، بحث عن الحساب في نافذة مستقلة، حقول سطر واضحة، وأخطاء حمراء تحت الحقول الناقصة أو المكررة.
6. **لا إسقاط صامت للأسطر:** الحفظ يفحص جميع الأسطر دون `Where` يستبعد غير المكتمل. تظهر رسالة على السطر ذي الحساب أو الدور الناقص؛ الأدوار المكررة لا تُرسل.
7. **فصل الحفظ عن النشاط:** يُنشأ الملف معطّلًا؛ حفظ ملف موجود لا يغير نشاطه أو نطاقه، والتحويل إلى نشط/معطل يتم بزر مستقل بعد تأكيد المستخدم وبيان الملف النشط الذي قد يتعطل.
8. **تحقق الخادم عند التفعيل:** يمنع تفعيل ملف بلا أسطر أو تنقصه أدوار دائمة مطلوبة أو يتضمن حسابًا غير مؤهل، مع إبقاء حماية التزامن وتفرد الملف النشط.
9. **عدد القواعد موثوق:** تسترجع خدمة القائمة أسطر الملفات الظاهرة بطلب واحد مجمع بدل الاعتماد على خاصية ملاحة غير محمّلة. لم تعد الشاشة ترسل طلب حساب منفصل لكل قاعدة في القائمة.
10. **التصميم متوافق مع المظاهر:** كل التنسيقات تعتمد على متغيرات مظهر OAS، مع تجاوب للشاشات الأصغر.

## الأدوار المعروفة في القوائم

- `Sales / SalesInvoice`: `SalesRevenue` مطلوب دائمًا؛ `TaxPayable` و`Inventory` و`COGS` تتوقف على المعاملة.
- `Purchasing / PurchaseReceipt`: `Inventory` و`GoodsReceivedNotInvoiced` مطلوبان.
- `Purchasing / PurchaseInvoice`: `GoodsReceivedNotInvoiced` مطلوب؛ `PurchaseTax` و`PurchasePriceVariance` مشروطان.
- `Accounting / CustomerAdvanceApplication`: `CustomerAdvances` مطلوب.
- `Optical / OpticalBreakage`: `ProductionDamageExpense` و`Inventory` مطلوبان.

**مهم:** فحص المتطلبات العامة هنا ليس شهادة جاهزية لجميع السيناريوهات المحاسبية؛ ما زال ترحيل المشتريات يستخدم فحص الجاهزية الخاص به الذي يفحص التواريخ والإعدادات والمورد والعملات. لم تُنشأ محركات ترحيل جديدة ولم يُغيّر منطق احتساب الأرصدة أو القيود المالية.

## اختبارات يجب تنفيذها على بيئة .NET

1. `dotnet restore OASSystem.sln`
2. `dotnet build OAS.Application/OAS.Application.csproj -c Debug --no-restore`
3. `dotnet build OAS.Client/OAS.Client.csproj -c Debug --no-restore`
4. `dotnet test OAS.Tests/OAS.Tests.csproj -c Debug --no-restore --filter PostingProfile`
5. من صفحة `/accounting/posting-profiles`، جرّب مرشحات الوحدة ونوع المستند والحالة مع أكثر من صفحة، وتحقق من العد الإجمالي.
6. أنشئ ملفًا جديدًا دون حساب في أحد الأسطر؛ يجب ظهور خطأ بجواره، وعدم حفظ جزء من الأسطر.
7. اضغط «إضافة الأدوار المقترحة» ثم اختر حسابات مؤهلة واحفظ. يجب أن يكون الملف **معطلًا**.
8. افتح الملف المحفوظ وفعّله. يجب إظهار تأكيد، وذكر الملف النشط السابق في النطاق نفسه إن وجد، ثم ظهور الحالة الجديدة بعد إعادة التحميل.
9. جرّب تعطيل حساب مرتبط ثم إعادة تفعيل الملف؛ يجب أن يمنع الخادم التفعيل.
10. افتح ملفًا قديمًا فيه دور غير معروف، وتأكد من عرض رمزه والمحافظة عليه عند القراءة. اختبر المظهر الداكن وسماء وشمس، ودقة 1366×768، والتبويبات وإغلاق تعديل غير محفوظ.

## مستوى التحقق في بيئة إعداد الملفات

- **تم:** فحص سلامة ملفات المصدر، اتساق المسارات، تركيب شروط التصفية، تحليل CSS، واختبارات سلامة ZIP.
- **لم يتم:** تشغيل البناء أو اختبارات NUnit أو التحقق من قاعدة بيانات SQL Server؛ لا يتوفر .NET SDK في هذه البيئة.

## ملاحظات قبل التسليم

تغيير دلالة `CreatePostingProfileRequest.IsActive` مقصود: القيمة الافتراضية أصبحت `false`، والخادم يرفض إنشاء ملف نشط مباشرة. كذلك يرفض الخادم تغيير الحالة أو الوحدة/نوع المستند من خلال تحديث بيانات ملف موجود؛ استخدم مسار الحالة المنفصل أو أنشئ ملفًا جديدًا للنطاق الآخر. يجب مراجعة تكاملات API الخارجية التي كانت تعتمد سلوك التفعيل الضمني.
