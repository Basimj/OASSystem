# إصلاح وتوحيد واجهات الموردين — OASSystem

تاريخ التنفيذ: 2026-10-31

## المشكلة الأولى: استعلام أرصدة الموردين

في `SupplierApReportingQueryService.GetSupplierBalancesAsync` كان شرط حذف الأرصدة الصفرية يأتي بعد إنشاء إسقاط يحوّل السجل المفقود في LEFT JOIN إلى صفر. هذه البنية سببت تعبير LINQ غير قابل للترجمة عند `LongCountAsync` في EF Core. نُقل شرط التصفية إلى ما قبل الإسقاط، على بيانات التجميع نفسها، مع الإبقاء على العد والتجميع والتصفية والتنقل بين الصفحات داخل SQL، دون تحويل جميع السجلات إلى الذاكرة.

## المشكلة الثانية: التوقف عند ترحيل افتتاحيات الموردين

أضيف فحص قراءة فقط عند الضغط على زر ترحيل الدفعة: نشاط المورد ووجود حساب له، نشاط الحساب وقبوله الترحيل وأن يكون من نوع أستاذ مساعد ضمن الخصوم وطبيعته دائنة؛ ويُراجع الحساب الأب المباشر لكونه حسابًا تحكميًا نشطًا ضمن الخصوم وطبيعته دائنة. عند الفشل تظهر رسالة Snackbar بالعربية ولا يُرسل أمر Post. لم يتغير `PostSupplierOpeningBatchCommandHandler` ولا `ProfileAccountingPostingService` ولا `SupplierSubledgerPostingPolicy`؛ تظل حماية الخادم هي المرجع النهائي، وقد يحدث تعارض إذا تغيرت البيانات بعد الفحص.

## المشكلة الثالثة: شكل الموردين وتبويبات الصفحات

- أضيف مكوّن `SupplierRelatedPageHeader` بتصميم التبويبات المختصر المتبع في العملاء.
- أضيفت حالة جلسة scoped لتحفظ تبويبات الموردين المفتوحة والمسودات والبحث والتصفية والصفحة عند الانتقال إلى المركز المالي أو التقارير ثم العودة.
- أزيل الرأس القديم المكرر من قائمة الموردين، وحُوّل المركز المالي وأعمار الديون والأرصدة الافتتاحية إلى الرأس المختصر الموحد.
- أُعيد تنسيق أزرار الأقسام في مركز المورد، وبقيت جميع وظائفها الأصلية وربطها باستعلاماتها.
- أُضيفت رسائل المنع/الإخفاق المنبثقة في عمليات التحميل والتصدير والافتتاحيات بدل عرض نص الاستثناء الخام.

## الاختبارات الموصى بها بعد فك الملفات

1. `dotnet build OASSystem.sln` ثم `dotnet test OAS.Tests/OAS.Tests.csproj`.
2. فتح الموردين وإنشاء تبويبين، والانتقال إلى المركز المالي والعودة، والتأكد من حفظ التبويبات والمسودات.
3. تجربة أقسام مركز المورد الستة: الملخص، كشف الحساب، الفواتير، سندات الصرف، المرتجعات، أوامر الشراء/GRNI، ومراقبة استجابة API.
4. من أعمار الديون: تصدير Excel لأرصدة الموردين مع استبعاد الأرصدة الصفرية وتضمينها، واختبار البحث وترقيم الصفحات.
5. إعداد مورد بحساب غير صالح للترحيل، ثم محاولة ترحيل دفعة افتتاحية: يجب ظهور Snackbar وعدم إرسال POST؛ ثم تصحيح الحساب وإعادة المحاولة.
6. تجربة الثيم المظلم والواجهة RTL والتمرير في أحجام 1366×768 و125% تكبير.

## حدود التحقق

تم فحص وجود المسارات واتساق أسماء العقود وخصائص DTO وتحليل صياغة CSS وسلامة أرشيف ZIP. لم تتوفر dotnet CLI أو قاعدة SQL Server هنا، لذا لم يتم تشغيل بناء أو اختبارات فعلية، ولا يمكن الجزم بزوال كل توقف دون تشغيل المشروع.
