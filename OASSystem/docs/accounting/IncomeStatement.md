# قائمة الدخل وتصنيف الحسابات

- لا يحتاج هذا الإصدار إلى Migration جديدة إذا طبقت Migration تصنيف القوائم المالية السابقة.
- الحساب المستقل الجديد (رئيسي أو ترحيل) يتطلب تصنيفاً متوافقاً. حقوق الملكية ذات تصنيف ضمني واحد. الحساب الفرعي الجديد يرث التصنيف ديناميكياً ولا يقبل تحديد تصنيف مستقل؛ التصنيفات الخاصة القديمة محفوظة كما هي.
- لإنشاء فروع مالية مختلفة يلزم إنشاء حسابات مستقلة مصنفة، أو استخدام الفروع المصنفة سابقاً. لا يُعاد تصنيف الشجرة أو القيود القديمة.
- أزيل زر التصنيف الجماعي من شاشة الشجرة. مُنع مسار التصنيف الجماعي القديم من تجاوز قفل الحسابات الفرعية.
- عند استيراد الحسابات بقالب Excel الجديد، حدد FinancialStatementCategory للحسابات المستقلة واتركه فارغاً للحسابات الفرعية. القيم بالإنجليزية من Enum، كما هو الحال في بقية حقول القالب.
- تقرير /accounting/reports/income-statement يعتمد على الحركات المرحلة في حسابات الإيرادات والمصروفات، بالمبلغ الدائن ناقص المدين. تستبعد قيود الإقفال وسلسلة العكس المرتبطة بها، دون استبعاد الحركات العكسية العادية. الحسابات غير المصنفة تدخل في صافي النتيجة مع تنبيه.
- تعرض الإيرادات التشغيلية بالصافي وفق القيود؛ الخصومات والمرتجعات المسجلة في نفس الحساب لا يعاد خصمها.
- عرض شهري حتى 12 شهراً؛ المقارنة تستخدم سعر صرف نهاية الفترة الحالية لكلا الفترتين (عرض فقط). مركز التكلفة يشمل الحركات المسندة إليه فقط. البحث يضيّق تفاصيل العرض دون تغيير المجاميع. عند التجميع حسب المستوى قد تظهر فروع أعمق إذا لم يكن الأب من نفس التصنيف، حفاظاً على التصنيف الصحيح. لا يفتح كشف حساب للتجميعات الجزئية أو مركز التكلفة لأن كشف الحساب لا يطبق نطاق القائمة نفسه.
- يلزم بناء المشروع وتشغيل اختبارات NUnit وتجربة الاستعلام على SQL Server. لا تتوفر بيئة .NET SDK أو SQL Server في الحاوية المستخدمة.
