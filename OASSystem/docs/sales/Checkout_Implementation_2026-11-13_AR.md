# تنفيذ واجهة بيع جديد / إتمام البيع — OASSystem

**التاريخ:** 2026-11-13  
**المسار:** `/sales/checkout`  
**المصدر:** `OASSystem_New_Sale_Checkout_Audit_2026-11-13_AR.md` وصورة تصميم «إتمام البيع» المعتمدة.  
**نسخة الأساس:** `OASSystem_Customer_Order_PostApproval_UI_Full_2026-11-13.zip`.

## ما تم تنفيذه

1. واجهة RTL جديدة مع شريط عنوان وتبويبات تنقل، عمود لبيانات الطلب والتوفر والتوريد وعمود للملخص المالي والسداد، ومجموعة أزرار سفلية. تنسيقات معزولة في `checkout-approved.css` ومحمّلة بعد الثيم العام؛ تدعم الوضع المظلم والشاشات الأصغر.
2. السماح بخطة **دفع كامل** دون دفعة جديدة عندما يكون الرصيد المتبقي مغطى بالعربون، مع تجنب إضافة سطر دفع صفري افتراضي.
3. منع تجاهل أسطر دفعات صفرية أو سالبة؛ والتحقق من العملة، والصندوق أو البنك أو حساب التسوية، ورقم الشيك مع رسائل مجاورة للحقول قبل الإرسال.
4. إضافة مسار **معاينة قراءة فقط** للدفعات (`POST api/sales/orders/{orderId}/checkout-preview`) يستخدم خدمات التسوية وأسعار الصرف الفعلية، ويعيد المبلغ بعملة الأساس وقيمته في عملة الطلب والمتبقي المتوقع. لم نعد نجمع مبالغ عملات مختلفة حسابيًا على الشاشة.
5. مقارنة أهلية البيع الآجل **بالعملة الأساسية** مع استخدام سعر صرف الطلب، لا مقارنة الحد الأساسي بمبلغ بعملة الطلب.
6. نافذة تأكيد قبل إهدار تعديلات الدفعات عند تغيير الطلب أو تحديثه أو الانتقال إلى صفحة الطلبات، وكذلك قبل مسح الدفعات عند التحويل للبيع الآجل.
7. اختيار الطلبات المؤهلة على الخادم **قبل الترقيم**، مع البحث برقم الطلب واسم العميل أو رقمه أو هاتفه.
8. فتح تبويب طلب العميل المحدد من الواجهة، وفتح الفاتورة المرتبطة عندما تكون موجودة، وعدم تقديم زر إعادة إتمام البيع بدل عرض الفاتورة.
9. تحسين تسمية زر مركز المبيعات من «بيع مباشر» إلى «إتمام طلب»؛ لأن هذه الصفحة تُتم بيع طلب موجود، والبيع المباشر من محرر فاتورة المبيعات.
10. الإبقاء على مفتاح إعادة المحاولة عند تحديث سياق **الطلب نفسه**، وعدم السماح بضغطة إتمام ثانية بينما العملية جارية. لم تُغيَّر قواعد المخزون أو ترحيل الفاتورة أو التسليم.

## الحدود والقيود

- **لم يُختبر البناء أو التشغيل**: لا يتوفر .NET SDK أو SQL Server في البيئة الحالية. تم إجراء فحص ساكن للروابط والمسارات وبنية Razor وCSS وZip فقط.
- منع التكرار بشكل مضمون **بين خوادم متعددة وعند إعادة المحاولة بعد فشل شبكة** يتطلب سجل Idempotency دائمًا وفهرسًا فريدًا واختبار تزامن SQL Server؛ لم يضف هذا التعديل مخطط قاعدة بيانات جديدًا. الحماية الحالية من حالة الطلب باقية.
- حساب التوفر أثناء التحصيل ومطابقة العملات يتطلبان اختبارًا على قاعدة بيانات المستخدم. معاينة الصرف لا تغيّر المبالغ المعتمدة على الخادم عند الحفظ.
- لا تُعرض أرقام تجربة من الصورة؛ جميع البيانات تُؤخذ من الطلب المحدد والخدمات الخلفية.

## خطوات التركيب

انسخ الملفات المعدلة إلى **نفس مساراتها** داخل `OASSystem`، ثم نفذ `Build > Clean Solution` و`Build > Rebuild Solution`. إذا كانت قاعدة البيانات تعمل بالفعل فلا حاجة لترحيل جديد لهذا التعديل؛ ثم حدّث المتصفح بـ `Ctrl + F5` وتحقق من شاشة `/sales/checkout`.
