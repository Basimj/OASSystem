# تقرير إصلاح الوصفة اليدوية في طلبات العملاء — OASSystem

**التاريخ:** 14 نوفمبر 2026  
**القسم:** المبيعات ← طلبات العملاء ← إنشاء/تعديل طلب  
**النسخة الأساسية:** OASSystem_Optical_Lab_Full_Project_2026-11-14.zip

## أولًا: تشخيص سبب التعطل

في `CustomerOrderOpticalService.PrepareAsync`، تستند مطابقة العدسة إلى
`LensVariantResolver.ResolveAsync` الذي يشترط وجود SKU مفعل من نفس المنتج
مع `LensDetails` مطابقة للقيم `SPH/CYL/ADD` بدقة. قبل التعديل كانت عملية إنشاء الطلب
تبدأ أولًا، وعند عدم وجود المطابقة تُرمى `ConflictException`؛ وقد يتوقف المصحح
في Visual Studio عند نقطة رمي الاستثناء.

**لا يجوز تجاوز هذا التحقق تلقائيًا أو إنشاء صنف مخزني افتراضي:** الهوية المخزنية
المطابقة مهمة للحجز وطلب التوريد والفوترة.

## ثانيًا: التعديلات

1. إنشاء عقد `CustomerOrderOpticalPrevalidationRequest/Result/Issue` في `OAS.Contracts`.
2. إضافة نقطة `POST api/sales/customer-orders/optical/prevalidate` للقراءة فقط؛
   تستخدم `ILensVariantResolver.TryResolveExactAsync` التي ترجع `null` عند غياب SKU
   بدل رمي `ConflictException` لهذه الحالة. كما تستخرج قياسات الوصفة المخزنة عند الحاجة.
3. استدعاء الفحص قبل `CreateCustomerOrderResultAsync` أو
   `UpdateCustomerOrderResultAsync` من `SalesWorkspaceHost`. إذا فشل الفحص، لا يبدأ
   طلب الإنشاء/التعديل.
4. عرض سبب عدم المطابقة وقياسات SPH/CYL/ADD تحت بند العدسة المعني بإطار أحمر،
   وفتح البند تلقائيًا في المحرر عند وجود خطأ.
5. جعل SPH وCYL ظاهرين ومطلوبين للإدخال اليدوي؛ يُكتب CYL = 0 إن لم يوجد،
   ويصبح Axis مطلوبًا بين 1 و180 فقط إذا كانت CYL غير صفرية.
6. إبقاء ADD ظاهرًا عند الحاجة فقط، وطَيّ بيانات Prism / Prism Base / PD /
   Monocular PD / Fitting Height / VA ضمن «القياسات الإضافية (اختياري)».
   تظل القيم المحفوظة في النموذج ولا تُحذف عند الطي.
7. توضيح أن القياسات الإضافية ليست جزءًا من هوية SKU؛ وقد يحتاجها المعمل
   لاحقًا بحسب نوع العدسة والتجهيز.
8. فحص اتساق شروط الإدخال اليدوي في `CustomerOrderOpticalService` نفسه كحماية
   إضافية من طلبات API الأخرى.
9. إضافة اختبارات NUnit للتحقق من نتيجة SKU غير الموجود والموجود،
   وغياب CYL/Axis والعدسات التي لا تتطلب وصفة.

## ثالثًا: قواعد الإدخال

| القياس | قاعدة واجهة الطلب |
|---|---|
| العين OD أو OS | مطلوب لكل سطر عدسة طبية |
| SPH | مطلوب، الصفر قيمة صالحة |
| CYL | مطلوب، أدخل صفرًا عند عدم وجود استجماتيزم |
| Axis | مطلوب إذا كانت CYL غير صفرية، من 1 إلى 180 |
| ADD | يُدخل فقط إذا كانت الوصفة تتضمن إضافة قراءة |
| Prism / Prism Base | إدخال إضافي حسب الوصفة |
| PD / Monocular PD / Fitting Height | إضافية عند إنشاء الطلب؛ قد يحتاجها المعمل قبل التصنيع |
| VA | إضافة توضيحية إذا توفرت |

**تنبيه:** المقارنة المخزنية الحالية دقيقة؛ `ADD = null` و`ADD = 0`
قد يُعاملان كقيمتين مختلفتين في بيانات العدسة. لا يُغيَّر ذلك تلقائيًا حفاظًا
على هوية SKU. إن لم يوجد مطابق يلزم تعريفه أو اختيار عدسة معرفة فعليًا بالمخزون.

## رابعًا: نطاق الإصلاح وقيوده

- لا تغييرات على المخزون، ولا إنشاء آلي لـ SKU، ولا تغيير لاحتساب التوريد أو الفوترة.
- يجنّب الفحص المسبق استثناء SKU المفقود في المسار العادي لإنشاء الطلب؛
  تبقى حماية الخادم النهائية، وقد يعود تعارض عند تغير بيانات المخزون بين الفحص والحفظ
  أو عند ظهور مشكلة أخرى منفصلة.
- لم يُنفذ `dotnet build` أو `dotnet test` أو اختبار SQL Server، لأن .NET SDK
  غير متوفر في بيئة إعداد الحزمة. تمت مراجعة الاتساق البرمجي وفحص سلامة الأرشيفات فقط.

## خامسًا: حالات اختبار التشغيل المطلوبة

1. اختر عدسة بوصفة يدوية وأدخل SPH=1 وCYL=0 وADD فارغًا، مع تعريف SKU مطابق:
   يجب اجتياز الفحص المسبق وحفظ الطلب.
2. اختر قياسات لا توجد لها `LensDetails` مطابقة: يجب فتح بند العدسة وعرض خطأ
   داخل النموذج **قبل** طلب الحفظ، دون دخول `LensVariantResolver.ResolveAsync`.
3. اترك CYL فارغًا: يجب عرض رسالة إدخال CYL=0 إن لم يوجد استجماتيزم.
4. أدخل CYL غير صفرية واترك Axis فارغًا: يجب ظهور خطأ المحور.
5. افتح/أغلق القياسات الإضافية وتأكد من احتفاظ النموذج بالقيم عند الطي.
6. جرّب وصفة محفوظة بقياسات موجودة وأخرى غير موجودة في المخزون.
7. جرّب طلبًا يضم إطارًا وعدستين؛ يجب إظهار الخطأ عند سطر العدسة غير المطابق فقط.
8. نفّذ Clean ثم Rebuild Solution مع تشغيل API وBlazor؛ واختبر كل ذلك على SQL Server.
