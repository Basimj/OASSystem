# تنفيذ واجهة متابعة طلبات العملاء — OASSystem

**التاريخ:** 2026-11-13  
**المسار:** `/sales/order-tracking`  
**المرجع:** `CustomerOrderTracking_Approved_Reference.png` وتقرير `OASSystem_Customer_Order_Tracking_Audit_2026-11-13_AR.md`.

## ما نُفذ

- إعادة تصميم الواجهة على غرار الصورة المعتمدة: تبويبات RTL من جهة اليمين، ست بطاقات مؤشرات مختصرة، شريط بحث وفلاتر، جدول قابل للتمرير أفقيًا، ولوحة تفاصيل جانبية يسار الجدول.
- تمييز عدد **البنود المستوفاة والناقصة** عن **الكميات**؛ الكميات المطلوبة والمحجوزة والنواقص تظهر في تفاصيل البنود، دون تقديم أعداد البنود كأنها أرصدة مخزون.
- إضافة إجراءات: «فتح طلب العميل»، «فتح النواقص»، «فتح أمر المعمل»، «التسوية والتسليم» وفق البيانات المتاحة.
- إصلاح اختيار «طلبات اليوم» ثم «متأخرة»: تبديل المؤشر يزيل نطاق التاريخ السابق بدل تراكم الفلاتر بصمت.
- مؤشرات الخادم تستثني الحالة والتوفر والتأخر **وتاريخ إنشاء الطلب** لتجنب تضييق بقية البطاقات بمجرد الضغط على «طلبات اليوم»؛ تظل بقية الفلاتر العامة ضمن نطاق المؤشرات، ويوضح ذلك داخل الصفحة.
- الاحتفاظ بالفلاتر ورقم صفحة النتائج في خدمة الحالة scoped عند مغادرة الصفحة والعودة إليها ما دامت جلسة Blazor قائمة.
- إظهار شرائح مرشحات فعالة مع إمكانية إزالة المرشح ومسح الكل، وعرض وقت آخر تحميل ناجح والتنبيه الدائم عند فشل التحديث.
- إزالة تكرار نتائج الطلب عند تعدد أوامر المعمل عبر اختيار أمر معمل واحد ذي أولوية (نشط أولًا، ثم أحدث مُسلَّم) بدل الربط بجميع الأوامر؛ وتفاصيل الطلب تستخدم اختيارًا واحدًا بدل `SingleOrDefaultAsync` على عدة سجلات.
- الحفاظ على خدمات الحجوزات والتوريد والمعمل والصلاحيات ومحاسبة النظام دون تعديل قواعد العمل أو قاعدة البيانات.

## اختبارات القبول المطلوبة على جهاز المطور

1. بناء `OASSystem.sln` باستخدام .NET 9 وإعادة تشغيل API وBlazor. لم يُنفَّذ البناء في جلسة إعداد هذه الحزمة لعدم وجود .NET SDK.
2. افتح `/sales/order-tracking` بدقة 1366×768: تظهر المؤشرات الستة والتبويبات باليمين والتفاصيل باليسار دون فقد الإجراءات.
3. اختر «طلبات اليوم» ثم «متأخرة»: يجب ألا تبقى حدود تاريخ اليوم مفعلة.
4. جرّب حالة طلب يحتوي على بند كميته 10 والمحجوز 6: يجب أن تظهر كمية نقص 4 في التفاصيل، بينما يظهر **عدد البنود** في القائمة.
5. طلب له أمر معمل نشط وأمر مُسلّم قديم: يظهر صف واحد للطلب، ولا يفشل فتح التفاصيل. هذا اختبار تكامل SQL Server **لم يُشغَّل بعد**.
6. البحث بالطلب/العميل/الجوال/الصنف والفلاتر المتقدمة؛ ثم فتح طلب عبر زر «فتح طلب العميل» والعودة: تستعاد حالة البحث والصفحة.
7. تعطيل API أثناء تحديث المتابعة: يظهر خطأ واضح بدل عرض نجاح وهمي، وتبقى آخر بيانات ناجحة مع توقيتها.
8. فتح التوريد والمعمل والتسوية من تفاصيل طلب مؤهل، والتأكد من الانتقال إلى المستند المقصود.
9. مراجعة الوضع المظلم والألوان والثيمات، وتجربة شاشة أصغر لضمان التمرير الأفقي للجدول.
10. مقارنة نتائج البطاقات مع استعلام SQL حقيقي على نفس نطاق البحث والفلاتر.

## حدود التحقق

تمت مراجعة البنية والأسماء والصياغة وفحص CSS ساكنًا وفحص ضغط الحزم. **لم يُشغَّل .NET ولا SQL Server ولا التطبيق في متصفح**. لذا فإن سلامة ترجمة EF Core للاستعلام الجديد والمطابقة البصرية الفعلية لا تزالان بحاجة إلى الاختبارات المذكورة.
