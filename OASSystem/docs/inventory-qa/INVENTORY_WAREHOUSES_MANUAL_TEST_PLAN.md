# Inventory V1 — Warehouses UI Manual Test Plan

## الهدف
اختبار واجهة `/inventory/warehouses` يدويًا والتأكد أن الإدخال غير الصحيح لا يوقف البرنامج، وأن البيانات تنتقل كاملة UI → API → DB → UI.

## معيار التحقق المرئي
### الحقول الإجبارية
- يظهر `*` أحمر بجانب Label.
- عند الحفظ والقيمة فارغة يظهر الحقل باللون/التوهج الأحمر.
- تظهر رسالة صغيرة تحت الحقل: `هذا الحقل إجباري.`.
- يظهر Snackbar: `هناك بيانات إجبارية لم يتم إدخالها.`.

### الحقول الاختيارية
- لا تظهر نجمة حمراء.
- يظهر `(اختياري)` في Placeholder عندما يكون الحقل فارغًا وقابلًا للتحرير.

### القيم غير الصحيحة
- يظهر الخطأ على الحقل نفسه.
- يظهر Snackbar يطلب مراجعة الحقول الحمراء.
- لا يحدث unhandled exception أو Blazor circuit failure.

## 1) إنشاء مخزن
- [ ] الضغط على `جديد` يفتح نموذجًا فارغًا، والحالة تكون نشطة افتراضيًا.
- [ ] حفظ النموذج فارغًا: يظهر الخطأ على `كود المخزن` و`اسم المخزن بالعربية` مع Snackbar العام.
- [ ] كود المخزن مطلوب وحده الأقصى 32 حرفًا.
- [ ] الاسم العربي مطلوب وحده الأقصى 100 حرفًا.
- [ ] الاسم الإنجليزي اختياري وحده الأقصى 100 حرفًا.
- [ ] الوصف اختياري وحده الأقصى 500 حرف.
- [ ] تجربة كود موجود مسبقًا: يظهر خطأ `هذا الكود مستخدم مسبقًا.` ولا يتوقف البرنامج.
- [ ] إنشاء مخزن صحيح غير افتراضي ثم تنفيذ اختبار Round-trip.
- [ ] إنشاء مخزن صحيح كافتراضي عندما لا يوجد مخزن افتراضي آخر.
- [ ] عند وجود مخزن افتراضي آخر، محاولة إنشاء مخزن افتراضي جديد تظهر رسالة موضعية ولا يتم الحفظ.

## 2) تعديل مخزن
- [ ] اختيار مخزن ثم الضغط `تعديل` يعرض جميع القيم الحالية كما هي.
- [ ] كود المخزن يظهر لكنه غير قابل للتعديل.
- [ ] تعديل الاسم العربي ثم الحفظ وإعادة الفتح يعيد القيمة نفسها.
- [ ] تعديل الاسم الإنجليزي والوصف ثم التحقق DB → UI.
- [ ] تفريغ الاسم العربي ثم الحفظ يظهر خطأ الحقل ولا يتم الإرسال.
- [ ] تغيير الحالة من نشط إلى غير نشط يحفظ ويعود بالقيمة نفسها إذا لم يكن المخزن افتراضيًا.
- [ ] محاولة تعطيل مخزن وهو `افتراضي` تظهر:
  - خطأ على `المخزن الافتراضي` أو `المخزن نشط`.
  - لا يتم إرسال تحديث غير صالح.
- [ ] محاولة جعل مخزن ثانٍ افتراضيًا مع وجود مخزن افتراضي آخر تظهر خطأ موضعي.
- [ ] إلغاء تحديد `افتراضي` عن المخزن الحالي ثم الحفظ، وبعدها يمكن تعيين مخزن آخر كافتراضي.
- [ ] زر `إلغاء` أثناء التعديل يعيد جميع القيم الأصلية دون حفظ.

## 3) البحث والقائمة
- [ ] البحث بالكود يعرض المخزن الصحيح.
- [ ] البحث بالاسم العربي يعرض المخزن الصحيح.
- [ ] البحث بالاسم الإنجليزي يعرض المخزن الصحيح.
- [ ] البحث بجزء من الوصف يعرض المخزن الصحيح.
- [ ] مسح البحث يعيد جميع المخازن.
- [ ] عمود `الافتراضي` يعكس IsDefault بدقة.
- [ ] عمود `الحالة` يعكس IsActive بدقة.
- [ ] اختيار صف لا يسمح بتغيير البيانات قبل الضغط على `تعديل`.

## 4) اختبار Round-trip القياسي
استخدم قيمًا مميزة، مثل:
- Code: `QA-WH-001`
- NameAr: `مخزن اختبار QA 001`
- NameEn: `QA Warehouse 001`
- Description: `Warehouse round-trip test`

ثم:
1. احفظ من الواجهة وتأكد من Snackbar النجاح.
2. نفذ `verify-inventory-warehouse.sql` بعد ضبط `@WarehouseCode`.
3. قارن Code/NameAr/NameEn/Description/IsDefault/IsActive مع المدخلات.
4. اضغط `تحديث` في الواجهة.
5. افتح المخزن نفسه وتأكد أن كل الحقول عادت بالقيم المخزنة في DB.
6. عدّل عدة حقول، احفظ، ثم أعد الخطوات 2–5.

## 5) اختبارات سلامة مهمة
- [ ] لا يوجد أكثر من مخزن واحد ظاهر كـ`افتراضي` بعد الاختبارات اليدوية.
- [ ] لا يوجد مخزن `IsDefault = 1` و`IsActive = 0`.
- [ ] لا توجد أكواد مخازن مكررة.
- [ ] لا توجد قيم تتجاوز أطوال SQL الفعلية.

## شرط إغلاق اختبار الواجهة
لا ننتقل إلى شاشة أرصدة المخزون حتى:
- جميع الحالات أعلاه Passed.
- لا يوجد unhandled exception أو توقف للبرنامج.
- كل قيمة محفوظة في DB تعود في UI كما هي.
- لا توجد قيمة يقبلها Application ثم ترفضها DB بسبب طول معروف.
