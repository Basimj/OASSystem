# Inventory V1 — Inventory Balances UI Manual Test Plan

## الهدف
اختبار واجهة `/inventory/balances` يدويًا باعتبارها واجهة **Read-only**، والتأكد أن جميع أرصدة المخزون تُعرض بصورة صحيحة وكاملة، وأن البحث/الفلترة/التنقل لا تسبب توقف البرنامج أو Blazor circuit failure.

## قاعدة مهمة
هذه الشاشة ليست CRUD ولا تحتوي Create/Update/Delete. أي تغيير على الرصيد يجب أن ينتج من عمليات المخزون أو الجرد، وليس من شاشة الأرصدة.

## 1) التحميل والعرض الأساسي
- [ ] فتح `/inventory/balances` يعرض الصفحة بدون Exception.
- [ ] أثناء التحميل تظهر رسالة `جاري تحميل أرصدة المخزون...` ثم تختفي.
- [ ] عند عدم وجود أرصدة تظهر رسالة Empty State ولا يحدث خطأ.
- [ ] زر `تحديث` يعيد جلب البيانات ولا يكرر الصفوف.
- [ ] الصفحة تعرض جميع الأرصدة وليس أول 200 سجل فقط.
- [ ] إذا كان هناك أكثر من 200 Product/Variant/Warehouse فإن الأسماء ما زالت تُحل بصورة صحيحة ولا تظهر `—` بسبب paging ناقص.

## 2) القيم المطلوبة في كل صف
لكل رصيد اختر سجلًا معروفًا من قاعدة البيانات وقارن:
- [ ] اسم المنتج صحيح.
- [ ] Product Code صحيح.
- [ ] Variant Name صحيح، أو `—` إذا لم يكن له اسم.
- [ ] SKU صحيح.
- [ ] Barcode صحيح، أو `—` إذا كان فارغًا.
- [ ] اسم المخزن صحيح.
- [ ] On Hand مطابق لقاعدة البيانات ويعرض **3 منازل عشرية**.
- [ ] Reserved مطابق ويعرض **3 منازل عشرية**.
- [ ] Available = On Hand - Reserved ويعرض **3 منازل عشرية**.
- [ ] On Order مطابق ويعرض **3 منازل عشرية**.
- [ ] Average Cost مطابق ويعرض منزلتين عشريتين.
- [ ] Inventory Value مطابق ويعرض منزلتين عشريتين.

## 3) اختبار الدقة العشرية
استخدم أو أنشئ عبر منطق المخزون سجلًا بقيم مثل:
- OnHand = `12.345`
- Reserved = `1.234`
- OnOrder = `2.567`

المتوقع:
- [ ] On Hand يظهر `12.345` وليس `12.35`.
- [ ] Reserved يظهر `1.234`.
- [ ] Available يظهر `11.111`.
- [ ] On Order يظهر `2.567`.
- [ ] لا يحدث rounding بصري يفقد الدقة المخزنة للكميات.

## 4) البحث
جرّب البحث بالقيم التالية كل واحدة على حدة:
- [ ] اسم المنتج العربي.
- [ ] اسم المنتج الإنجليزي إن وجد.
- [ ] Product Code.
- [ ] Variant Name.
- [ ] SKU.
- [ ] Barcode.
- [ ] اسم المخزن.
- [ ] جزء من النص وليس النص كاملًا.
- [ ] البحث لا يتأثر بحالة الأحرف في النصوص اللاتينية.
- [ ] مسح البحث يعيد جميع الصفوف.
- [ ] قيمة بحث غير موجودة تعرض Empty State بدون Exception.

## 5) فلتر المخزن
- [ ] `كل المخازن` يعرض جميع الأرصدة.
- [ ] اختيار مخزن نشط يعرض أرصدته فقط.
- [ ] المخزن غير النشط إذا كانت له أرصدة يظهر في القائمة مع `(غير نشط)` ويمكن فلترته.
- [ ] تغيير الفلتر عدة مرات لا يكرر البيانات ولا يغير قيم الأرصدة.
- [ ] الجمع بين البحث وفلتر المخزن يعطي التقاطع الصحيح.

## 6) فتح تفاصيل الصنف
لكل صف:
- [ ] زر الصنف يفتح `/products?productId=...`.
- [ ] يتم فتح المنتج الصحيح، وليس Variant آخر.
- [ ] بيانات المنتج المعروضة تطابق المنتج المرتبط بالـProductVariant في DB.
- [ ] العودة إلى الأرصدة لا تسبب فقدان أو فساد البيانات.

## 7) فتح حركات الصنف
لكل صف:
- [ ] زر الحركات يفتح `/inventory/ledger?variantId=...`.
- [ ] صفحة Ledger تُفلتر بالحقيقة على ProductVariant المختار.
- [ ] لا تظهر حركات Variant آخر بسبب تجاهل Query String.
- [ ] إذا لم توجد حركات للصنف تظهر Empty State طبيعيًا ولا Exception.

## 8) سلامة العرض عند البيانات الناقصة/غير المتوقعة
هذه حالات دفاعية؛ لا يفترض حدوثها مع سلامة FKs، لكن يجب ألا توقف البرنامج:
- [ ] Barcode = NULL يعرض `—`.
- [ ] VariantName = NULL يعرض `—`.
- [ ] LastMovementAtUtc = NULL لا يسبب خطأ حتى لو لم يكن معروضًا في الجدول.
- [ ] OnHand/Reserved/OnOrder = 0 تظهر كأرقام صحيحة.
- [ ] Available = 0 يظهر بصورة صحيحة.
- [ ] API error مصرح به يعرض Feedback للمستخدم ولا يوقف الصفحة.
- [ ] Exception غير متوقع أثناء التحميل يعرض رسالة الخطأ العامة ولا يترك Blazor circuit في حالة مكسورة.

## 9) اختبار اكتمال البيانات (> 200 سجل)
لأن `PageRequest.MaximumPageSize = 200`:
- [ ] عند وجود 201 رصيد أو أكثر، العدد الظاهر يساوي إجمالي السجلات المتوقع.
- [ ] ابحث عن سجل تعرف أنه في صفحة API الثانية وتأكد أنه يظهر في الواجهة.
- [ ] كرر الاختبار مع أكثر من 200 ProductVariant إذا أمكن، للتأكد أن أسماء المنتجات/SKU تُحل لكل الصفوف.

## 10) اختبار DB ↔ UI
1. اختر SKU معروفًا.
2. نفذ `verify-inventory-balances.sql` بعد ضبط `@Sku` أو `@WarehouseCode`.
3. سجّل قيم DB: Product/Variant/SKU/Barcode/Warehouse/OnHand/Reserved/Available/OnOrder/AverageCost/InventoryValue.
4. افتح واجهة الأرصدة وابحث بنفس SKU.
5. قارن كل قيمة واحدةً واحدةً.
6. نفذ عملية مخزون صحيحة تغيّر الرصيد.
7. اضغط `تحديث` في الأرصدة.
8. نفذ SQL مرة ثانية وتأكد أن UI وDB متطابقان بعد الحركة.

## شرط إغلاق اختبار الواجهة
لا ننتقل إلى شاشة عمليات المخزون حتى:
- جميع الحالات أعلاه Passed.
- لا يوجد Create/Edit/Delete في واجهة الأرصدة.
- لا يوجد unhandled exception أو Blazor circuit failure.
- القيم المعروضة تطابق DB، خصوصًا دقة الكميات 3 منازل.
- البحث والفلترة والتنقل تعمل بالقيم الصحيحة.
- الصفحة لا تقطع النتائج عند 200 سجل.
